# 诊断浮层的布局取消修复（2026-10-24）

基于0e70f4f继续既有UI交互修复，不增加暂缓的语义服务或其他功能。

## 两项已登记失败的原因

1. 正常窗口确有生产问题：点击诊断后，一次全局布局通知会无条件关闭浮层。调用栈定位到MainActivity.buildEditor中的全局布局监听器；当时文档版本、光标和可见区域数值没有变化。
2. 原290dp小窗用例的前提过期：新工作台减少占用后，编辑区仍有170px高，可以容纳浮层，因此没有打开详情是合理行为。将无空间兜底用例改到真正不足的220dp窗口，同时增加290dp仍保留浮层的独立回归；没有在生产逻辑里强制小窗一律弹对话框。

## 修复及测试

DiagnosticPopup在显示时保存文档/版本/光标/位置/可见区域锚点。全局布局通知现在核对这些信息，只有确实变化或锚点不可用时才关闭。同一错误重复刷新时保持显示；错误内容改变或显式清除时关闭旧浮层，SoraEditorPort.clearDiagnostics同步通知界面。编辑、选区、滚动、失焦和生命周期的原取消机制保留；浮层仍只读，不抢编辑器焦点，不改文本。

新增6项主Main/Sora回归：290dp紧凑大字体窗口、重复无变化布局后仍可查看、字号改变后关闭旧位置浮层、现有真实括号结构检查结果的点击展示、同一诊断刷新与内容变更、显式清除诊断。最后一项来自现有分析器实际报告，不注入伪造的编译器错误，也不声称完整语义分析。

原长消息用例保留完整文字、滚动、复制原文及焦点断言；真正小窗额外核对至少一行文字可见、末条消息能够滚动到完整可见位置。截图中的“诊断布局验收”明确是UI夹具，另有“基础括号检查”的真实结构分析截图。

57项相关测试通过。首次完整测试/Debug实际打包成功；补充滚动末行断言后，再次严格全量回归成功。原两个失败用例现在通过，未删除或跳过断言。
