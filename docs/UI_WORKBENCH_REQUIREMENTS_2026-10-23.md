CodePocket UI 工作台全面重构任务

你现在继续开发现有的 Android IDE 项目 CodePocket。

此前我已经提供过完整开发需求，包括 C++ / Python 运行环境、文件管理、智能补全、语法高亮、流畅动画、虚拟键盘、蓝牙键鼠、权限管理、终端等功能。

这些需求全部保留。

本次任务重点是重新设计整个 UI 工作台的布局结构与操作逻辑。

我已经提供了一张手绘布局图。这张图是新版 UI 的核心参考，同时结合下面的详细说明进行实现。

不要简单修改几个按钮的位置，也不要只是换一种主题颜色。我要的是一套接近桌面版 VS Code、同时针对 Android 手机和平板优化的专业 IDE 工作台。

设计原则：

专业、现代、简洁、精致。

扁平化设计，统一线性图标。

尽可能还原 VS Code 的信息架构。

二、最重要的布局架构

完整工作台采用以下区域：

顶部菜单与工具栏

左侧固定 Activity Bar

左侧主边栏 Primary Side Bar

中央代码编辑器 Editor

右侧辅助边栏 Secondary Side Bar

底部工作面板 Bottom Panel

底部状态栏 Status Bar

特别强调三个结构约束：

约束一：Activity Bar 贯穿整个工作区高度。

最左侧图标导航栏从顶部工作区一直延伸到底部，不因终端展开而中断。

约束二：左右侧边栏的内容只显示在终端上方。

左侧文件树和右侧网页面板位于编辑器所在的上层工作区。

底部终端横跨主边栏、中央编辑器、辅助边栏下方，但不覆盖 Activity Bar。

约束三：右侧辅助边栏允许移动到左侧。

网页默认从右侧辅助边栏打开，但允许通过面板菜单移动到左侧，也能重新移动回右侧。

这些是明确要求，不允许按照传统的「文件树贯穿到底部、终端仅位于编辑器下方」结构实现。

推荐布局结构：

顶部菜单栏 ├── Activity Bar（独立，贯穿工作区高度） └── 主工作区域 ├── 上方工作区 │ ├── Primary Side Bar │ ├── Editor │ └── Secondary Side Bar ├── Bottom Panel（横跨上面三个区域的总宽度） └── Status Bar

状态栏位于工作区底部，Activity Bar 与其在整体结构上保持独立。

三、顶部菜单栏

参考 VS Code，但不要机械复制桌面端全部菜单。

平板大屏可以显示：

文件、编辑、选择、视图、运行、终端、帮助。

手机上采用紧凑模式，仅保留核心入口，其余功能通过结构化菜单访问。

工具栏应支持：

当前项目名称

运行 / 停止

搜索

切换侧边栏

更多操作

要求：

工具栏保持单行。

不出现文字被挤成两行。

不出现按钮横向溢出。

不大量使用宽大的文字按钮。

高频操作尽可能一两步完成。

菜单分组明确，避免几十项功能堆积。

四、左侧 Activity Bar

最左侧固定导航栏是整套 UI 的重要部分。

采用类似 VS Code 的扁平线性图标。

建议包含：

Explorer：文件资源管理器

Search：搜索

Source Control：Git 源代码管理

Run：运行与调试

Web：网页浏览

Extensions：插件管理

Account：账户（有实际功能时再启用）

Settings：设置

设置入口固定靠近底部。

图标之间保持统一的尺寸、间距和视觉风格。

选中图标时出现清晰的选中指示条。

点击图标时：

未选中：切换至对应面板。

已选中：允许折叠对应面板。

再次点击：恢复对应面板。

面板切换有轻微动画，不要引起编辑器异常闪烁。

Activity Bar 不随文件树、网页面板、终端的展开和关闭而消失。

如果手机屏幕高度不足，优先保留高频入口，其他入口允许通过溢出菜单访问，不能让图标超出屏幕。

五、左侧主边栏 Primary Side Bar

默认显示文件资源管理器。

支持通过 Activity Bar 切换：

文件

搜索

Git

插件

其他扩展视图

支持：

新建文件和文件夹

展开、折叠多级目录

重命名、移动和删除

长按及鼠标右键菜单

文件搜索

未保存文件状态显示

文件操作优先集中在资源管理器内，而不是放在顶部的超长菜单中。

边栏支持：

拖动宽度

展开、隐藏

宽度记忆

根据窗口大小自动调整

平滑过渡动画

边栏只延伸到终端顶部，不覆盖底部工作面板。

需要支持：

多文件标签页

标签页关闭

未保存状态标记

C++ / Python 精细语法高亮

VS Code 风格智能代码补全

参数提示

括号匹配和配对着色

行号和缩进参考线

代码折叠

查找替换

自动缩进

光标平滑移动及闪烁

撤销与重做

蓝牙键鼠交互

安卓虚拟键盘适配

要求编辑器具有最小可用宽度。

当打开双侧边栏导致编辑器空间不足时，根据规则优先收起辅助边栏，而不是无限压缩代码编辑器。

保留各文件的光标位置、滚动位置、编辑状态和独立标准输入数据。

右侧辅助边栏默认用于内置网页浏览，但并不局限于浏览器。

7.2 网页面板左右移动

网页默认显示在右侧。

用户可以通过面板菜单执行：

「移至左侧边栏」 「移至右侧边栏」

移动时要求：

不关闭当前网页。

尽可能保留网页状态。

不破坏文件资源管理器。

左侧面板可以在网页与文件树之间切换。

保存用户选择的网页面板位置。

重新打开 App 后恢复设置。

除了网页，其他兼容的辅助视图未来也可支持左右移动。

9.1 位置关系

终端位于主工作区域底部。

它需要横向贯穿：

左侧主边栏区域 + 中央编辑区 + 右侧辅助边栏区域。

但不能覆盖 Activity Bar。

这是本次最重要的布局验收点之一。

需要支持：

收起

复制输出

在终端最大化状态下，必须保留恢复和关闭入口。

终端打开和关闭不能重置编辑器内容或网页状态。

Activity Bar 应保持独立，不能被状态栏错误遮挡。

十一、平板横屏布局

平板横屏是完整工作台的设计基准。

默认使用：

Activity Bar + 左侧资源管理器 + 中央编辑器 + 可选右侧网页 + 底部终端。

支持同时显示左右双侧边栏。

支持鼠标拖动：

左侧边栏宽度

右侧边栏宽度

终端高度

允许同时查看代码、项目文件和网页文档。

但应始终保证编辑器的最小可用空间。

右侧辅助栏建议默认关闭或按用户上次状态恢复，避免第一次启动时编辑器过窄。

十二、平板竖屏布局

保留 Activity Bar 和中央编辑器。

默认可以显示左侧文件树。

右侧辅助边栏改为按需展开。

打开网页时，可以根据空间：

折叠文件树

临时显示网页面板

切换到网页专注视图

用户仍能手动切换网页位置。

终端位于下方，支持拖动和最大化。

不能因屏幕旋转导致文件未保存内容丢失。

十三、手机横屏布局

手机横屏具有较宽但较矮的可用空间。

采用紧凑工作台：

固定 Activity Bar

中央编辑器优先

文件树按需展开

网页辅助栏按需展开

终端默认折叠或较低高度

避免同时强制打开三个狭窄的纵向面板。

可以根据横屏宽度展示双栏，但不应因为布局变化导致编辑器高度过小。

终端支持专注模式及最大化。

十四、手机竖屏布局

这是触屏使用的重点。

保持极简的主编辑视图。

默认：

紧凑顶部工具栏

左侧窄 Activity Bar

中央编辑器占主要宽度

左侧文件树默认隐藏

右侧网页默认隐藏

终端默认折叠或紧凑显示

14.1 文件树

点击文件图标时，以抽屉或临时覆盖面板的方式显示文件树。

选择文件后可以自动返回编辑器。

避免让文件树永久挤占手机编辑器宽度。

14.2 网页

手机竖屏中，网页可以使用专注视图或临时辅助面板。

不强制与代码编辑器并排。

需要可以快速切回代码，尽可能保留网页浏览状态。

仍然允许用户设置网页属于左侧或右侧，但实际呈现方式应服从小屏幕空间限制。

14.3 虚拟键盘

虚拟键盘弹出后：

编辑器自动调整可用高度

光标保持可见

补全弹窗不被遮挡

终端与侧边栏合理避让

可以主动关闭键盘

支持紧凑的编程符号快捷栏

实体键盘连接时，不强制弹出虚拟键盘。

十五、响应式布局机制

请基于窗口实际可用尺寸设计，而不是仅根据设备型号判断。

建议初始断点：

小于 600dp：手机紧凑布局

600–999dp：中等窗口布局

1000dp 及以上：完整大屏布局

这些数值可以根据真实组件尺寸和测试结果调整。

必须考虑：

安卓手机

安卓平板

横屏和竖屏

分屏模式

自由窗口

鸿蒙卓易通兼容环境

系统字体大小和显示缩放变化

当窗口大小变化时，尽量平滑转换布局，同时保留编辑状态。

十六、动画和视觉规范

本次 UI 重构继续遵守之前的动画要求。

包括：

文件夹展开

补全弹窗

动画必须自然、克制。

图标统一采用扁平化线性风格，参考 VS Code Codicon 的视觉语言。

提供深色和浅色主题。

不要使用大量卡片、拟物化按钮、厚重阴影或无意义的视觉装饰。

十七、交互行为要求

请统一所有设备上的操作逻辑。

点击文件图标打开或关闭资源管理器。

点击网页图标打开网页辅助面板。

允许网页左右移动。

点击运行执行当前文件，并显示相应终端会话。

文件切换不能丢失未保存内容。

编辑器、终端、文件树、网页应各自保存必要状态。

系统返回键优先关闭当前弹窗、临时面板或专注视图。

鼠标支持右键菜单、滚轮与拖动。

触屏支持长按菜单与拖动调整。

蓝牙键盘支持常见 VS Code 快捷键。

面板切换不应无故夺走编辑器焦点。

面板尺寸不能被拖动到不可操作的程度。

防止连续快速点击导致面板状态错乱。

关闭辅助面板不应销毁不必要的内容状态。

目标不是简单把手机版做得像桌面软件，而是建立一套真正适合 Android 的 VS Code 风格工作台。

尤其不能再出现以下问题：

全部功能堆积在菜单中

文件操作入口混乱

终端与侧边栏层级错误

网页面板只能固定在一侧

手机屏幕被多个面板挤占

平板无法利用大屏空间

UI 只是更换颜色而没有改善操作逻辑

请先检查当前代码，再分阶段实施。

可以在确保兼容的前提下重构工作台布局，但不要无意义地修改底层编译器、文件系统或其他无关模块。

最后请汇报：

修改的 UI 架构。

新的工作台布局层级。

四种设备布局的实现情况。

左右侧边栏和终端的交互实现情况。

网页面板左右移动功能的实现情况。

APK 构建及测试结果。

尚未完成的功能和实际限制。

最终目标：像 VS Code 一样专业，像原生 Android 应用一样流畅、自然、好用。
