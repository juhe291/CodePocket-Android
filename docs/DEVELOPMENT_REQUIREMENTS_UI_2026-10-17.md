# CodePocket Android IDE 完整开发需求与重构任务

你现在负责继续开发我现有的 Android 项目 **CodePocket**。

CodePocket 是一款面向安卓手机、平板的轻量级 C++ / Python 集成开发环境（IDE），主要用于编程学习、算法练习和日常代码编写。

目前已经有一版可以使用的程序，但在 UI 布局、编辑体验、运行效率、虚拟键盘适配、文件管理等方面存在明显问题。

我希望把它逐步打磨成一款具有 VS Code 专业感，同时真正适合安卓触屏和外接键鼠操作的 IDE。

**请严格遵循以下要求。**

---

# 一、开发基本原则

1. 首先阅读现有仓库全部相关代码、README、Gradle 配置、GitHub Actions 工作流。
2. 在现有项目上继续开发，不要无理由创建新项目或整体推倒重写。
3. 可以重构 UI 和编辑器架构，但必须保持功能兼容和文件数据安全。
4. 当前仓库的实际代码是判断已有功能的唯一依据，不要假设此前需求都已实现。
5. 优先使用成熟、维护活跃、许可证兼容的开源组件。
6. 优先保证稳定性、流畅度和真实运行能力。
7. 不允许使用假的编译结果、模拟的运行输出冒充真实功能。
8. 所有重要修改都要进行测试，尽可能实际构建 APK。
9. 如果环境缺少 Android SDK、模拟器或真机，明确说明哪些功能未验证。
10. 不要为了视觉效果牺牲代码编辑性能。
11. 保持项目模块化，便于后续维护及软件著作权相关材料整理。
12. 不要一次性实现全部需求，应按照后面的阶段计划逐步推进。

# 二、UI / UX 整体重新设计（重点）

目前 CodePocket 的 UI 存在以下问题：

- 顶部工具栏非常臃肿。
- CodePocket 标题受到挤压，甚至换行。
- 部分功能按钮超出屏幕。
- 新建文件、新建文件夹、导入、导出等按钮大量堆积。
- 编辑器、输入框、输出区之间缺少清晰的视觉层级。
- 文件管理方式不像专业 IDE。
- UI 元素尺寸、间距、对齐方式不统一。
- 手机有限的显示空间没有得到合理利用。

我希望进行系统性的 UI 重设计，而不是简单换颜色。

## 2.1 整体设计风格

主要参考：

- Visual Studio Code — Dark Modern / Light Modern
- VS Code 的 Explorer、Editor、Terminal 布局
- Android Studio 的现代工具栏和图标设计
- Android 原生应用的触摸交互规范

视觉关键词：

**现代、专业、简洁、扁平化、紧凑、精致、低饱和度、清晰层次。**

具体要求：

1. 默认提供深色主题，同时支持浅色主题、跟随系统。
2. 统一颜色体系、字体层级、间距、按钮高度、边框和圆角。
3. 所有图标采用统一的扁平化线性设计，参考 VS Code Codicon 风格。
4. 避免拟物化、复杂渐变、大面积阴影、过度圆角和装饰卡片。
5. 使用微妙的背景差异、分隔线和选中状态区分各面板。
6. 不常用功能收纳进菜单，不允许顶部堆积大量大型文字按钮。
7. 减少无意义的留白，优先为代码编辑器提供空间。
8. 所有弹窗、菜单、工具提示、文件树都使用一致的视觉规范。
9. 状态栏、面板标题栏应尽量紧凑。
10. 避免文本截断、横向溢出、组件错位。

可以定义统一的 Design Tokens，例如主题颜色、间距、尺寸和字体规范，避免每个组件自行决定样式。

## 2.2 手机竖屏布局

采用紧凑的 VS Code 风格布局。

顶部：

- 单排主工具栏。
- 左侧资源管理器入口。
- 中间简洁显示项目或文件名称，不允许换行。
- 右侧保留运行按钮和更多菜单。
- 其他操作通过菜单、长按或文件资源管理器完成。

编辑区：

- 顶部横向可滚动多文件标签栏。
- 显示当前文件及必要的路径信息。
- 代码编辑器占据主要显示区域。
- 不常驻显示快捷键说明。
- 不允许工具栏挤占大量高度。

底部：

- 可展开、收起的终端面板。
- 简洁状态栏。
- 虚拟键盘弹出时自动合理调整布局。

## 2.3 手机横屏布局

- 根据可用宽度灵活使用分栏布局。
- 文件树可以作为侧边面板展开。
- 编辑器占据最大可用区域。
- 终端可以放在底部或适当位置。
- 支持手动调整面板大小。
- 不允许因为横屏而出现无意义的大面积空白。

## 2.4 平板布局

重点参考桌面 VS Code：

- 最左侧 Activity Bar。
- 左侧 Explorer 文件资源管理器。
- 中间多标签代码编辑器。
- 底部集成终端。
- 右下或底部显示状态信息。

需要支持：

- 鼠标拖动调整侧边栏宽度。
- 拖动终端面板高度。
- 隐藏、显示、最大化面板。
- 横竖屏及分屏窗口切换。
- 尽量保留当前编辑状态。

请使用窗口实际可用尺寸进行响应式布局，而不是简单通过设备型号判断手机还是平板。

# 三、流畅动画系统

我希望 CodePocket 具有流畅、细腻、克制的动画。

具体包括：

1. 光标平滑移动。
2. 光标自然闪烁。
3. 标签页切换过渡。
4. 文件树展开、折叠动画。
5. 侧边栏展开、隐藏动画。
6. 终端展开、收起和最大化动画。
7. 代码补全弹窗的出现与消失动画。
8. 菜单和弹窗的轻量过渡。
9. 深浅主题切换时适当使用颜色过渡。
10. 按钮点击、选中、焦点变化具有统一反馈。

要求：

- 以 60 FPS 为基本流畅目标。
- 在高刷新率设备上尽量匹配屏幕刷新率。
- 光标动画不能引起输入延迟或定位错误。
- 快速输入时优先保证编辑性能。
- 动画持续时间应短而自然，不要过度炫技。
- 支持减少动画、关闭动画。
- 尊重系统的动画缩放及减少动态效果设置。

优先实现稳定的动画，不要为动画重新实现不必要的底层编辑器功能。

# 四、专业代码编辑器

## 4.1 C++ / Python 语法高亮

当前代码颜色太单一，需要参考 VS Code 的语法主题。

支持 C++ 和 Python 独立的语言解析及高亮规则。

至少区分：

- 关键字
- 基本数据类型
- 类名与自定义类型
- 函数名称
- 成员方法
- 变量及参数
- 数字
- 字符串
- 注释
- 常量
- 预处理指令
- 命名空间
- 运算符

Python 另外支持：

- 装饰器
- f-string
- 内置函数
- True、False、None
- import、from、as
- 类方法及属性

C++ 另外支持：

- STL 类型和常用函数
- 模板
- #include 等预处理指令
- 命名空间
- 类、结构体、成员函数

还需实现：

- 当前行高亮。
- 缩进参考线。
- 匹配括号高亮。
- 错误下划线。
- 多种编辑器配色主题。

主题至少包含 Dark Modern / Light Modern 风格。

真正的语义高亮优先使用成熟解析技术，避免仅用简单正则表达式处理所有情况。

## 4.2 VS Code 风格智能补全

这是重要功能。

不能只依靠简单关键词前缀匹配。

目标是逐步实现类似 IntelliSense 的使用体验：

1. 输入时自动展示补全候选列表。
2. 根据上下文推荐变量、函数、类型和成员。
3. 支持 C++ 的 `.`, `->`, `::` 成员补全。
4. 支持 Python 的 `.` 属性和方法补全。
5. 支持函数参数提示。
6. 支持类型信息和简短文档。
7. 支持常用标准库 API。
8. 支持代码片段 Snippets。
9. 支持智能缩进和括号自动补全。
10. 候选项带有不同类型图标。
11. 支持上下方向键选择。
12. 支持 Tab、Enter 接受候选。
13. 支持 Esc 关闭弹窗。
14. 支持触屏点击补全项。
15. 弹窗要跟随光标，避免被虚拟键盘遮挡。
16. 支持补全结果排序、过滤和滚动。
17. 设置中可以控制自动触发、手动触发及接受补全的按键。

技术方面：

- 评估 Sora Editor 等成熟安卓代码编辑器组件。
- 评估 Tree-sitter 或等效增量解析技术。
- C++ 语义补全研究 clangd / LSP。
- Python 语义补全研究 Jedi、Pyright 等可行方案。
- 优先考虑设备性能和鸿蒙卓易通兼容性。

如果完整 LSP 暂时无法实现，应采用分层架构：

基础词法补全 → 项目符号补全 → 语义补全。

不要把简单关键词补全宣传为完整 IntelliSense。

## 4.3 基础编辑能力

需要具备：

后续可以扩展多光标编辑，但不作为当前第一优先级。

# 五、安卓虚拟键盘与蓝牙键鼠

## 5.1 虚拟键盘

目前虚拟键盘弹出后，编辑区容易受到挤压，输入体验较差。

要求：

1. 键盘弹出后正确调整可用布局。
2. 光标所在位置始终保持可见。
3. 不允许编辑器或补全窗口被键盘遮挡。
4. 可以主动关闭虚拟键盘。
5. 提供明确的收起键盘操作。
6. 键盘关闭后恢复原来的面板布局。
7. 支持编程快捷符号栏。

快捷符号栏可包含：

Tab、`{}`、`[]`、`()`、`;`、`=`、`:`、方向键。

快捷栏要紧凑，并允许在设置中关闭。

## 5.2 蓝牙键盘和鼠标

支持常用快捷键：

- Ctrl+S：保存
- Ctrl+N：新建文件
- Ctrl+O：打开文件
- Ctrl+F：查找
- Ctrl+H：替换
- Ctrl+Z：撤销
- Ctrl+Y：重做（兼容 Ctrl+Shift+Z）
- Ctrl+B：切换文件管理器
- Ctrl+Space：智能补全
- F5：运行
- Tab：缩进或接受补全
- Shift+Tab：减少缩进
- Esc：关闭菜单或补全窗口

鼠标需要支持：

- 光标精确定位
- 文本选择
- 滚轮滚动
- 右键上下文菜单
- 面板尺寸拖动
- 文件拖动（可行时实现）

外接实体键盘时，不应强制弹出系统虚拟键盘。

# 六、VS Code 风格文件管理

文件管理器必须采用树状目录结构，而不是使用顶部一排按钮来执行所有操作。

需要支持：

1. 新建文件。
2. 新建文件夹。
3. 打开文件。
4. 文件重命名。
5. 文件夹重命名。
6. 删除文件和文件夹。
7. 移动文件。
8. 多层目录展开、折叠。
9. 按文件类型显示不同扁平图标。
10. 通过标签页打开多个文件。
11. 显示未保存状态。
12. 恢复上次打开的工作区。
13. 文件搜索。
14. 重要删除操作需要确认。

## 6.1 手机真实目录

我希望项目文件可以保存在手机实际目录中，而不是只能存放在 App 内部存储。

优先使用 Android Storage Access Framework（SAF）：

- 由用户选择工作区目录。
- 保存持久化目录授权。
- 在授权目录中创建和编辑文件。
- 支持工作区切换。
- 避免使用不必要的全盘文件管理权限。
- 不能因为 App 卸载而丢失用户明确保存在外部工作区的源码。

文件操作应避免目录越界、误覆盖和误删除。

注意 Android 版本、设备厂商和卓易通可能存在不同的文件访问限制，需要做兼容处理。

# 七、C++ 和 Python 运行环境

## 7.1 Python

保留现有的本地 Python 运行方案。

需要支持：

- Python 3 代码执行。
- 常用标准库。
- 标准输入输出。
- 运行时异常。
- traceback。
- 多文件模块导入。
- 支持项目文件路径。
- 运行超时与中止机制。

需要检查 Chaquopy 的实际版本和依赖兼容性。

## 7.2 C++

当前 C++ 使用 Wandbox 云端编译，实际使用时感觉比较慢。

希望优先研究本地 C++17 编译运行方案。

研究目标：

- 本地 Clang 或其他可行工具链。
- 常用 C++ 标准库、STL。
- iostream、vector、algorithm、string、queue、map 等。
- 支持多文件编译。
- 支持编译错误和运行错误定位。

注意：

- 不要假设 Android NDK 自带的 Clang 可以直接作为普通 App 的运行时编译器。
- 必须评估安卓可执行文件限制、架构兼容、工具链体积和分发许可证。
- 如果本地方案短期不可行，保留现有云端编译作为可用的后备方案。
- 不允许为了实现本地编译而破坏当前能用的云端运行功能。
- 云端运行时必须明确说明源码和输入会发送到第三方服务。

最终希望在条件允许时提供本地/云端运行模式切换。

## 7.3 标准输入隔离

目前不同语言和文件的标准输入容易共用同一份内容。

请修改为：

- 每个代码文件独立保存测试输入。
- 切换文件时恢复对应输入。
- 切换 C++ / Python 时不互相覆盖。
- 支持保存多组测试数据。
- 关闭并重新打开项目后可按设置恢复相关输入。

# 八、高度拟真的程序运行终端

我希望终端在视觉和交互上尽可能接近 VS Code 集成终端。

**但不需要实现完整 Linux Shell。**

只用于编译、运行和交互程序。

## 8.1 外观

- 使用真正适合终端的渲染组件。
- 等宽字体。
- 闪烁光标。
- 真实终端网格。
- ANSI 颜色。
- 支持长输出滚动。
- 支持复制和文本选择。
- 终端内容不应像普通多行输入框。
- 避免额外插入大量无意义的运行提示。

可以评估 xterm.js 或适合 Android 的终端渲染方案。

## 8.2 操作

需要支持：

- 实时程序输出。
- 在终端内直接输入数据。
- 按 Enter 提交输入。
- 停止当前程序。
- 清空终端。
- 复制运行结果。
- 查看执行时间。
- 查看退出码。
- 显示运行中、等待输入、运行结束等状态。
- 支持程序运行记录。
- 支持不同文件的运行会话。

不要设计独立的大型 stdin 文本框长期占据编辑空间。

可以保留「预设标准输入」作为算法测试模式，但应与终端模式清楚区分。

## 8.3 终端面板布局

参考 VS Code：

- 默认位于编辑器底部。
- 支持拖动高度。
- 支持隐藏。
- 支持展开。
- 支持最大化。
- 手机、平板采用不同布局策略。
- 虚拟键盘弹出时合理避让。

终端包含「终端」「问题」「输出」等标签。

说明：

如果当前执行引擎不能提供实时交互，不允许假装实现。应明确展示当前模式的限制，后续通过持续运行的进程或会话机制实现。

## 8.4 终端使用说明

第一次打开时显示简洁的中文说明。

说明：

- 如何运行程序。
- 如何输入数据。
- 如何停止程序。
- 如何复制输出。
- 如何清空终端。
- 编译错误与运行错误的区别。
- 当前运行模式及其限制。

增加帮助入口，用户可以再次查看说明。

# 十、权限管理

按照 Android 最小必要权限原则实施。

要求：
