# CodePocket — Codex 开发需求与分阶段实施计划

> 交接说明：请在**当前已有的 CodePocket 项目仓库/工作区**上继续开发，不要新建一个空项目或直接整体重写。当前版本号、构建环境、已实现功能、所用库均应以仓库实际代码为准；此前的方案曾采用 Kotlin Android + Chaquopy 本地 Python + Wandbox 云端 C++，但不要未经核查就假设当前代码仍然如此。
>
> **先审查、列计划、修复构建与关键缺陷，再分阶段实现。每完成一个可验证的阶段就反馈结果，不要一口气完成所有功能。**

## 1. 产品定位与统一设计原则

将 CodePocket 打造成以**简体中文为默认语言**、适合 Android 手机与平板的轻量级 **C++ / Python IDE**：整体视觉、工作区、标签页、终端及设置参考 VS Code 的交互体验，同时适合触屏与物理键鼠。

- 默认简体中文，预留英文切换；不照搬第三方软件的源代码、品牌素材或图标。
- 界面采用一致的扁平化线性图标体系（如符合法律许可的 Codicon 风格），清晰紧凑、避免拟物与花哨渐变。
- 支持深色、浅色、跟随系统主题，记住设置。编辑器配色可独立于 App 主题选择。
- 采用**基于实际窗口宽度的响应式布局**，适配手机竖屏、手机横屏、平板横竖屏及可变窗口。布局改变时不应丢失光标、滚动位置、未保存内容、文件标签和运行状态。
- 稳定性、文件安全、输入体验优先于效果和功能数量；不做仅能展示却不能工作的按钮。

## 2. 已反馈的现有问题（首先确认并修复）

1. **C++ 云端运行慢**：定位瓶颈，优化编译器信息缓存、请求链路和反馈；评估本地 C++ 编译/执行可行性（原生工具链、ABI、运行限制、体积、许可证、安全），给出实际测试数据。若暂时无法本地运行，保留稳定云端回退并明确标记联网与源码上传，不虚称“本地/离线”。
2. **文件管理不像 VS Code**：由单独或混乱的文件入口调整为可展开/折叠的树状资源管理器，具备工作区、嵌套目录和多文件标签页。
3. **不同语言共享标准输入**：至少按 C++/Python 分开保存，进一步应按每个打开的文件（稳定 URI/项目内 ID）独立保存 stdin，切换语言、文件、项目不串数据。
4. **安卓软键盘适配差**：输入法弹出时编辑区域被严重挤压，光标/代码可视空间不足；键盘应可主动隐藏，关闭后布局恢复；不会因 IME、旋转或后台恢复而丢字。实体蓝牙键盘连接时不要强制弹软键盘。
5. **缺少设置页面**：实现分类设置中心、可保存并生效的设置项。
6. **C++ 与 Python 高亮过于单一**：分别使用适合该语言的词法规则；逐步支持更准确的语义着色。

## 3. 编辑器与 VS Code 风格工作区

### 3.1 布局

- **手机竖屏**：顶部紧凑工具栏 + 可折叠文件树入口 + 可横向滚动的编辑标签 + 尽量完整的编辑区 + 可折叠/拖拽/最大化的底部面板。键盘弹出时自动让出编辑空间（可配置自动折叠底部面板）。
- **手机横屏**：按可用宽度选择编辑区/运行区分栏或可切换面板，不固定死板的横向布局。
- **平板**：左侧可调整宽度的文件树，中间编辑器，底部或侧边可调整的运行面板；合理保留状态栏。
- 活动栏/资源管理器、标签页、未保存标记、当前路径、面板拖动条、底部状态栏参考 VS Code 的信息层次。状态栏显示语言、行/列、缩进、编码、运行状态等，点击可以进入相关设置。

### 3.2 编辑能力

- 保证选区、复制粘贴、撤销重做、自动缩进、自动闭合括号、括号匹配、行号、缩进参考线、自动换行、滚动与长按选择正确。
- 支持 **Tab** 插入缩进或接受补全、**Shift+Tab** 反缩进；**Ctrl+Space** 提示补全；至少包含关键词、常用函数和当前文件标识符，明确“基础补全”和真正语义补全的差别。
- 代码查找替换：Ctrl+F、Ctrl+H、Ctrl+G（跳转行）与项目内搜索，给触屏用户提供等价入口。
- 支持 C++ / Python 一键格式化；优先评估可靠格式化工具，不能实现时显示清楚限制。
- 软键盘上方可选“编程快捷键栏”：Tab、方向键、`{}`、`()`、`[]`、`;`、`=` 等；可关闭，并且与输入法、硬件键盘不冲突。
- 鼠标点击定位、拖选、滚轮、右键上下文菜单；键盘快捷键至少含 Ctrl+S/N/O/B、F5；如与安卓或输入法快捷键冲突，应给出替代入口。
- 支持错误定位：点击编译错误、traceback 或问题列表可跳到对应文件和行，做不到精准映射时不猜测。

### 3.3 代码颜色

- 内置至少 Dark+ / Light+ 风格主题，可扩展其他编辑器主题；UI 主题和语法主题分开保存。
- **C++**：预处理指令、头文件、关键字、基础类型、类/结构体/命名空间、函数/方法、变量/参数、数字、字符串、注释、常量、宏分别设置合适颜色；支持嵌套括号配色。
- **Python**：关键字、内置类型/函数、`def`/`class` 名称、参数/变量、装饰器、数字、字符串、注释、`True`/`False`/`None`、f-string 文本及表达式区分着色；缩进参考线、括号配对着色。
- 先确保词法高亮稳定、编辑不卡顿；语义高亮需真实解析器/语言服务支持，不要仅靠正则表达式假装已经完成。

## 4. 文件与项目管理（真实手机目录）

- 支持通过 Android **Storage Access Framework (SAF)** 由用户选择真实手机目录作为工作区，并在授权范围内新建文件/文件夹、展开/折叠、重命名、移动、删除、打开与保存；可重开最近工作区。
- 工作区及子目录以树形显示，支持 `.cpp`、`.h`、`.hpp`、`.py` 等，并对文件类型显示一致的扁平图标。支持多标签页、关闭标签、未保存提示、恢复最近会话。
- 不把文件默默只存在应用私有目录；如果执行引擎需要镜像到沙盒，应明确从 SAF 内容 URI 导入/同步并保证写回可靠。
- 对重命名/移动/删除做路径合法性、权限失败处理、未保存变更确认、删除确认；防止数据丢失。支持自动保存与崩溃后恢复（未写回的草稿须清楚区分）。
- 尽可能保证卸载 App 后用户选择的外部工作区文件仍保留；不承诺 Android 文件提供方无法支持的操作。
- 多文件 C++ 工程（多个 `.cpp`、头文件）与 Python 本地模块导入应逐步支持；可以配置入口文件，不假设所有程序都是单文件。

## 5. 运行引擎、标准输入与测试用例

- Python 优先本地离线运行，保证 `print()`、`input()`、常见标准库、异常栈以及多文件导入；不能阻塞 UI，需有取消/停止、超时与错误提示机制。
- C++ 优先研究**可行的本地编译方案**；若手机/卓易通环境不允许，则保留云端模式并优化启动延迟、网络错误反馈、编译器缓存；后端选型以实际可用性为准。清楚提示源码和 stdin 会发送至第三方。
- 标准输入以**当前文件为主键**保存，切换 C++/Python、文件、项目时不互相污染；提供“清空输入”。
- 运行面板区分编译错误、运行错误、网络错误、超时、中止、成功，并显示可信的耗时/退出码（获取不到不编造）。
- 增加算法测试用例管理：按文件存储多组输入与预期输出，支持运行全部、展示通过/错误/超时、实际输出对比与差异；默认比较规则写清楚，可选忽略末尾换行/空白。
- 提供基本的运行安全机制：一次运行限制、取消、超时、异常处理，避免长时间运行导致界面卡死。

## 6. 集成终端（强调：只运行程序，不提供 Shell）

**目标**：尽可能模仿 VS Code 的集成终端，而不是一个黑底输出 TextView。可以评估 xterm.js 或其他维护良好的终端渲染库，但要结合 Android 性能、生命周期、软键盘兼容及授权选择。

- **视觉**：等宽终端网格、ANSI 颜色/格式、光标闪烁、自动滚动、可滚动历史、文本选择复制、输入回显；流式输出，不故意把结果改造成提示卡片。
- **交互**：执行 Python/C++ 程序时在同一终端窗口输入数据并 Enter，支持软键盘/蓝牙键盘；运行中可停止。终端支持拖动面板高度、最大化、隐藏、恢复；手机和平板分别适配。
- **信息**：标签为“终端 / 问题 / 输出”；运行状态、退出码、耗时以准确、克制的方式呈现；终端顶部或右上角可打开中文使用说明。
- **边界**：不提供 `cd`、`ls`、`bash` 等操作系统 Shell；不应显示假的系统命令提示符或伪造执行步骤。若当前 Wandbox 等一次性远程接口不能实时交互，则采用预设 stdin 模式并明确告知用户，不能制作假交互。
- **说明示例**：“此终端只负责运行当前 C++/Python 程序，不支持系统命令。运行时可查看输出；执行引擎支持交互时可直接输入并回车。云端模式可能需要提前提供标准输入。”

## 7. 设置中心（必须做真实生效的设置）

- **外观**：简中/英文、深色/浅色/跟随系统、编辑器语法主题、界面缩放、扁平图标。
- **编辑器**：字体/字号、Tab 宽度（2/4/8）、空格/Tab、行号、换行、缩进参考线、括号着色、自动补全、格式化。
- **输入与键鼠**：软键盘自动弹出行为/手动收起、编程符号栏开关、IME 弹出时折叠运行面板、硬件键盘快捷键说明。
- **文件**：默认或最近工作区、自动保存、恢复标签、显示隐藏文件、删除确认。
- **运行**：默认语言/入口文件、真实可用的 C++ 运行模式、运行超时、终端字体、运行记录、标准输入按文件记忆。
- **布局**：侧边栏显示、底部面板行为、默认面板尺寸、平板适配。
- **隐私与权限/关于**：已授权目录、重新授权、网络传输说明、版本号、第三方许可证、问题反馈、首次使用帮助。
- 增加设置搜索（可分期）；未实现或不适用的选项必须隐藏/禁用并解释，不设置无功能开关。

## 8. 权限、隐私、设备兼容

- 权限按需申请，并在请求前用中文说明用途：文件夹授权（SAF）、可选通知权限。正常连接蓝牙键鼠不额外索取扫描/连接蓝牙权限；`INTERNET` 不需要运行时确认。
- 不默认申请 `MANAGE_EXTERNAL_STORAGE` 等大范围权限；避免与功能无关的权限。
- 覆盖标准 Android 手机与平板、横竖屏、蓝牙键盘/鼠标、多种 IME；**鸿蒙卓易通**列为必须验证的目标环境，关注 APK 安装、Chaquopy/原生库、SAF 文件选择、键盘/窗口行为。
- 实际设备不可用时，把它列为**未验证**，不得报告“兼容成功”。
- 第三方服务失败、网络断开、存储授权撤销都要有可理解的中文错误提示。

## 9. 中长期能力（勿阻塞第一版稳定版）

- Git 状态、文件差异、提交及 GitHub 仓库同步；不得未经用户许可上传项目或源代码。
- 更高级的 C++ clangd/语义补全与 Python 语言服务，须评估设备性能/体积。
- 自定义编辑器主题与更全面的格式化/项目级任务能力。

## 10. 实施顺序（必须分阶段）

**阶段 0：审查与建立基线**
1. 阅读 README、源码、Gradle、AndroidManifest、Actions 工作流和现有测试。
2. 列出“已实现/缺失/有缺陷”功能矩阵，标明复现步骤与风险；检查许可证。
3. 尝试执行现有测试和构建 Debug APK；记录具体命令、结果和日志。若构建环境缺失，说明缺失项，不谎称成功。
4. 给出文件级改动计划，再动代码；避免无必要重构。

**阶段 P0：可用性及数据安全（最高优先级）**
- 修复软键盘导致的空间挤压、无法主动关闭、焦点和光标丢失；确保横竖屏状态保存。
- 完成 SAF 工作区与基本文件树/文件夹管理、保存/恢复机制。
- 修复 C++、Python 及不同文件共用 stdin 的问题。
- 修复程序运行/中止、网络失败与崩溃恢复中的明显问题；保证已有 Python/C++ 功能不倒退。

**阶段 P1：核心 VS Code 体验**
- 手机/平板自适应布局、可调面板、标签页、平面化图标、状态栏。
- Dark+/Light+ 与完整基础高亮、软键盘快捷栏、硬件键鼠。
- 拟真程序终端（真实 I/O 能力以内）、终端说明、可用设置页、查找替换。

**阶段 P2：生产力功能**
- 本地 C++ 编译方案的原型验证与效果对比；若可行再正式集成。
- 多文件项目、批量测试用例、一键格式化、更高级补全。

**阶段 P3：后续增强**
- Git/GitHub 集成、设置搜索细化、主题扩展、更多语言分析。

每阶段应保持独立可编译、可回滚；**不要一次提交所有阶段的改动**。

## 11. 验收场景与交付方式

至少验证并逐项报告以下用例：

1. 手机竖屏打开 C++ 文件，弹出输入法，代码光标所在行仍可见；一键关闭输入法后编辑器恢复空间；可收起/最大化终端。
2. 手机横屏和平板横竖屏切换，文件树/标签/未保存内容/滚动状态不丢失。
3. 蓝牙键盘的 Tab、Shift+Tab、Ctrl+S、Ctrl+Space、F5 与鼠标右键/滚轮正常；冲突时有触屏替代。
4. 用户选择 `Documents/CodePocket` 一类手机目录作为工作区，新建文件夹及 `main.cpp`、`main.py`，编辑保存，重启 App 后在相同目录读回；删除与移动安全确认。
5. 在 C++ 文件输入 `3 5`，Python 文件输入 `10 20`，来回切换输入值不串；不同文件各有自己的值。
6. C++/Python 的关键字、类型/类、函数、字符串、注释和数字可见不同颜色；主题切换立即生效；Python f-string、装饰器和缩进展示合理。
7. Python 离线运行成功且报错可定位；C++ 在线运行失败时提示具体网络原因；不把预置 stdin 冒充实时交互。
8. 终端能选择复制输出、清空、停止、拖动、最大化及隐藏；说明入口可访问，且不提供 Shell。
9. 文件的多组测试用例可以批量运行和对比预期输出（P2 完成后）。
10. 尝试 GitHub Actions `assembleDebug`，若成功提供 APK artifact 的工作流证据；未拿到真实 APK 时标记“未构建验证”。
11. 在安卓手机/平板及鸿蒙卓易通分别记录“实测通过/实测失败/未验证”，不拿模拟器结果替代真机结论。

**每次交付回复格式**：
- 本阶段修改的文件与主要逻辑。
- 实际执行的构建/测试命令与结果（含失败原因）。
- 已验证功能、未验证功能、已知问题、回归风险。
- 下一阶段建议（下一阶段开始前先等我的确认）。

**额外要求**：持续维护 README、架构与用户使用说明、依赖/许可证清单，保留可证明原创开发过程的提交记录，以便后续发布与可能的软件著作权登记；不得把第三方源码当成完全原创代码。未经明确授权，不自动 push、发布 APK 或上传本地文件到第三方平台。
