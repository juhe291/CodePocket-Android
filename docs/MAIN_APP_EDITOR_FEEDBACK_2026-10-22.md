## 本批完成

- 真实Sora编辑区接回原有六层混合括号颜色，以及变量、参数、属性、常量和声明类型的词法配色。保持TextMate的关键字、字符串、注释等语法样式；光标旁的匹配括号加背景强调。
- 新样式层使用Sora公开Spans/Span扩展接口，读取时复制需要分段的样式，保留原字体样式、背景、下划线和颜色解析器。不修改上游解析器、IME、正文、选区或撤销记录。
- 原生CodeEditor内部回归与主Sora复用同一份EditorPalette，避免维护两套颜色。已有4.5万字符/6000项分析预算继续生效；样式缓存随语法刷新和文档变化失效，旧请求不能覆盖当前文件或组合输入。
- 修正保存失败提示：只有本次草稿真正写入后，才显示“恢复草稿仍保留”。草稿写入失败时明确说明“本次恢复草稿未写入”；超过20万字符时状态与阻止切文件弹窗均说明需要缩减或复制代码，不再显示空原因。原文件写入规则、冲突检查和操作失败保护保持。
- 手机深色、平板浅色语法的实际主控件渲染见[图像与检查范围](main-editor-feedback-preview/README.md)。这些是主机图形检查，不是实机截图。

这些属于I2的一批改动，不代表I2、I3或完整整合已完成。当前角色色仍由已有词法规则推断，不是类型检查、clangd/Jedi或LSP语义分析。

## 发现问题与原因

| 问题 | 原因与处理 |
| --- | --- |
| 主Sora缺少原括号/变量角色色 | I1的SoraEditorPort只接收诊断，忽略extraTokens/brackets。现在在TextMate之上接入独立只读样式层，保留原分析与版本保护 |
| 语法刷新可能覆盖或污染附加颜色 | 对上游Span直接改色会与异步TextMate及对象池冲突。本批使用不修改上游Span的读取层；样式替换/增量更新继续通过原接口，受影响行合并结果缓存 |
| 超长粘贴后草稿提示不真实 | 旧失败分支没有区分drafts.put与文件写入的失败。现在记录本次检查点实际是否成功，失败不再声称新草稿已保留 |
| 新增主机测试的反射访问失败 | 第一轮扩展用例通过包内实现类取得setStyles方法，遇到Java访问边界。改用Sora公开CodeEditor类的方法入口，未更改组件可见性或关闭检查；失败日志和JUnit保留 |
