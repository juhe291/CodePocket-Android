## P1：动画系统与补全界面

### 动画覆盖与输入约束

| 区域 | 计划行为 | 必须保持的行为 |
| --- | --- | --- |
| 光标 | 平滑移动、柔和平滑闪烁；支持分别关闭 | 文本与逻辑光标立即更新；点击、选区、输入法组合区与候选定位使用真实坐标，不能使用动画中间坐标替代 |
| 工作区 | 文件树展开/折叠、标签切换、侧边栏开关自然过渡 | 不丢文件焦点、未保存内容、滚动和 stdin；动画不触发保存或文件操作 |
| 终端面板 | 展开、收起、最大化/恢复自然过渡；拖动尺寸跟手 | 拖动直接反馈，不排队追赶手指；输出滚动、选择、运行与停止保持响应 |
| 补全弹窗 | 出现/消失使用轻微淡入或位移 | 首批候选与点击命中立即可用；快速输入、关闭或重新触发时取消旧动画 |
| 主题 | 深浅主题采用可选的柔和颜色过渡 | 保持文字可读、输入焦点、选区和布局；不能每帧重建 Activity 或重新解析整份代码 |

- 设置中提供持久化 App 动画总开关及光标移动/闪烁开关；默认尊重系统减少动画/关闭动画设置。系统要求减少或关闭时优先降级；App 关闭同样立即生效，不能强行覆盖系统限制。
- 关闭闪烁后光标保持可见；关闭过渡后直接显示最终状态。按 minSdk 24 评估系统设置读取和动态变化，未知设备行为必须记录，不宣称已支持。
- IME 弹出、窗口尺寸变化及光标可见性优先处理；必要时跳过动画，避免代码区域抖动。快速连续操作可取消并从当前状态衔接，后台/销毁时清理动画和回调。
- 编辑、组合输入、命中测试与滚动不等待动画；不得按每次按键做全树重建、全文件语义解析或重型布局。优先使用成熟组件和系统动画能力，不自行重造复杂编辑器底层。

### 候选列表、键鼠及片段

- 采用 VS Code 风格的可滚动候选列表，支持触屏点击、实体键盘导航及鼠标；提供候选类型图标和文字说明、简短文档区、函数参数提示位置。只显示有可靠来源的信息，未知类型不猜测；真实语义签名由 P2 提供，P1 可展示有明确来源的内置函数资料。
- 弹窗跟随实际光标，按编辑器滚动、窗口边界、系统栏与 IME 可见区域计算位置；空间不足时上下翻转、限制高度/宽度或收起文档区。不得遮住输入位置、被键盘盖住，或为展示弹窗强制弹出/关闭输入法。
- 提供持久化补全按键设置。建议默认：Tab 接受可见且有效的选中候选，否则缩进；Shift+Tab 反缩进；Enter 默认保留换行，可配置接受显式选中的候选；方向键仅在候选导航状态切换候选，否则移动光标；Esc 关闭弹窗且不修改文本；Ctrl+Space 主动请求。最终行为在设置和帮助中说明。
- 不截获输入法组合确认事件；不影响 Ctrl+S/N/O/B、F5 等已有快捷键，并为触屏保留等价入口。没有候选、焦点在 stdin 或终端、存在代码选区时分别测试，不能误吞按键。
- P1 增加明确标记的内置代码片段及占位符跳转，继续完善自动括号补全、智能缩进；片段接受应形成可撤销的一次编辑，定义 Tab 在占位符与候选间的优先级。P2 再接语言服务返回的片段和语义编辑范围。
- P1 仍可使用词法提供方，界面明确显示“基础词法补全”；预留语义提供方接口，不将 UI 完成视为深度语义完成。

### 分批实施顺序

1. P0 设备验收及回修后，先记录关闭动画的输入、光标、补全和布局基线；评估现有 EditText 增量方案与成熟编辑器组件，再确定最小改动范围。
2. 结合原 P1 设置、布局工作先实现真实生效的动画/按键设置及可调面板，再加侧边栏、树、标签、终端过渡；每批可单独构建及回滚。
3. 完成候选数据模型、列表、光标定位、IME 避让和键鼠规则，再接内置片段、资料与轻微弹窗动画；验证前保留现有稳定入口作为回退。
4. 依据组件验证结果增加平滑光标及可选主题过渡。若需迁移编辑器，先提供隔离原型与状态保留证据，确认范围后再替换，不为了动画直接整体重写。

## P2：C++ / Python 深度语义补全

- C++：基于实际作用域和类型提供变量、函数、类、成员方法、命名空间及常用标准库候选，支持 `.`、`->`、`::`，提供重载/参数提示和可获取的说明。
- Python：基于作用域、导入和可推断类型提供变量、函数、类、成员方法和常用标准库候选，支持 `.`、函数参数及说明；不为获得补全而执行用户代码。
- 正确处理未保存文本、不完整代码、项目内头文件/模块与文件切换。不要把从文档中收集到的同名标识符当成成员语义；无法确定类型时允许无结果并解释限制。
